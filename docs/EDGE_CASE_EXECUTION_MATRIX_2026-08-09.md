# Edge-Case Execution Matrix — 2026-08-09

## Purpose

This is a test execution and coverage map for high-risk migration, tax,
inventory, CRM, connector, and accounting boundaries. An **Existing** row names
an executable test already in the repository. A **New** row is an unimplemented,
test-only specification with its exact proposed location; it is not evidence
that the behavior currently exists.

All PostgreSQL scenarios must run against a disposable database. Do not point
these commands at a user, beta, or production database.

## Focused execution commands

Run commands from the repository root. The test-file argument is the path in
the matrix.

| Label     | Command                                                                                                                                                                                                                                                                 |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API-UNIT  | corepack.cmd pnpm --filter @clearledger/api exec vitest run --config vitest.config.ts <test-file>                                                                                                                                                                       |
| CORE-UNIT | corepack.cmd pnpm --filter @clearledger/accounting-core exec vitest run <test-file>                                                                                                                                                                                     |
| API-INT   | Set TEST_DATABASE_URL and DATABASE_URL to the same disposable PostgreSQL URL, run corepack.cmd pnpm --filter @clearledger/db run migrate:deploy, then run corepack.cmd pnpm --filter @clearledger/api exec vitest run --config vitest.integration.config.ts <test-file> |
| FULL-INT  | corepack.cmd pnpm test:integration. This deploys migrations before executing every API integration test.                                                                                                                                                                |
| ROLLBACK  | Set DATABASE*URL to a disposable database named clearledger_rollback_verify*\* and run corepack.cmd pnpm db:rollback:verify. The script refuses other database names unless its explicit destructive override is set.                                                   |

## Prioritized coverage gaps

These are coverage gaps, not findings that the product currently violates its
contracts. They are prioritized because a failure would threaten accounting
integrity, tenant isolation, or a high-volume external boundary.

1. **ACC-N1 — journal transaction fault injection.** Existing tests prove
   validation failures leave no partial state, but do not inject a failure in
   the middle of a successful posting transaction.
2. **MIG-N1 — financial-import commit recovery.** Master-data atomicity and
   duplicate commits are covered; a crash/fault between financial posting and
   migration finalization needs direct evidence.
3. **CON-N1 — concurrent inbound webhook replay.** One verified ingress and
   demo replay are covered, but a provider retry storm of the same signed event
   is not directly exercised.
4. **CRM-N1 — negative CRM mutation cases.** The current integration test
   proves the happy tenant-scoped workflow and zero-accounting boundary, not
   stale/cross-tenant contact and related-record mutation failures.
5. **INV-N1 — reservation lifecycle race.** Reservation creation/release and
   transfers/counts are covered separately, not at the last-unit concurrency
   boundary.
6. **TAX-N1 — effective-dated version change after draft.** Unit and setup
   tests prove calculation and immutable tax-code versions, but the document
   lifecycle needs a direct draft-to-post snapshot race assertion.

## Deliberate non-claim

Portable archive v3 is tested as a secret-free, integrity-checked export and
explicitly marks itself as not supporting an in-product full restore. Treat
MIG-N2 as a release-boundary assertion until a restore feature is expressly
authorized; do not convert it into an implied backup/restore promise.
