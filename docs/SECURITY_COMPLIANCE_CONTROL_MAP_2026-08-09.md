# Security and Compliance Control Map — 2026-08-09

**Scope:** a concise map of repository controls and the operating evidence needed to use
them in production. It does not claim SOC 2, ISO 27001, PCI DSS, tax, or privacy-law
certification, and it is not legal advice.

`Repository control` means the documented engineering boundary or locally evidenced
implementation exists. `Operating gate` means the deployment owner must configure, test,
approve, and retain evidence before production use.

## Control map

| Control family                                 | Repository control / evidence                                                                                                                                                                                                                                          | Operating gate and acceptance evidence                                                                                                                                                                            |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Governance and truthful claims                 | The commercialization plan separates implemented, review-only, gated, and missing capabilities; it prohibits unsupported certification claims.                                                                                                                         | Keep public claims, beta terms, support scope, and release evidence aligned. Obtain counsel review for privacy, DPA, terms, retention, and jurisdictional obligations.                                            |
| Identity and sessions                          | Production design uses OIDC authorization-code flow with PKCE, nonce/state, issuer/JWKS checks, verified email, MFA for finance roles, hashed rotating sessions, recent authentication, revocation, and append-only auth audit.                                        | Select/configure the identity provider, HTTPS, recovery, MFA, secret storage, and edge rate limiting; exercise login, recovery, revocation, invitation, and cross-tenant-denial checks.                           |
| Authorization and tenant isolation             | Default-deny, organization-scoped authorization is supplemented by forced PostgreSQL RLS, transaction-local tenant context, separate runtime/migration roles, and cross-tenant test requirements.                                                                      | Provision only unprivileged runtime access; review privileged maintenance/backup access and run wrong/missing/correct-context and pool-reuse evidence for new tenant surfaces.                                    |
| Accounting integrity and commercial separation | Immutable posted history, review-first imports, idempotency, period controls, and a commercial control plane with no accounting side effects are documented product boundaries.                                                                                        | Preserve source/reconciliation evidence and use explicit reviewed accounting workflows; do not use connector, payment, or browser state to silently post or settle records.                                       |
| Data protection and secrets                    | The requirements call for encryption in transit/at rest, encrypted backups, environment separation, secret rotation, restricted privileged access, and dependency/container scanning. Connector credentials are encrypted and retained provider payloads are redacted. | Use a managed secret store and encrypted storage; rotate and audit secrets; maintain separate runtime, migration, and backup credentials; record vendor regions, contracts, and offboarding plans.                |
| Application, files, and external interfaces    | HTTPS, HSTS, CSP, CSRF protection, secure cookies, validation/encoding, parameterized data access, upload allowlists, size limits, and correlation IDs are required. The threat model also specifies signature/replay checks and tenant-scoped storage controls.       | Supply production malware scanning, isolated render/worker environments, shared rate limiting, approved object storage, and monitored alert delivery; test new public routes and file types before release.       |
| Payment-card exposure and payment events       | Hosted payment pages, no PAN/CVV storage, signed webhooks, unique provider event IDs, idempotency, replay handling, redacted logs, and separate settlement reconciliation are required.                                                                                | Choose and contract a hosted processor; configure verified webhooks; test duplicates, reordering, refunds, cancellations, and chargebacks; do not claim PCI compliance without independent assessment.            |
| Audit, monitoring, and access review           | Append-only audit events include actor, organization, action/target, request data, and sensitive-value redaction. Operations define security-outcome logs and alert conditions.                                                                                        | Configure monitored alert delivery and a restricted breach register; review owners, finance access, migration access, secrets, and backup access at least quarterly and revoke access immediately on role change. |
| Backup and recovery                            | Managed encrypted backups, PITR, separate credentials, versioned/immutable storage, named-operator restore access, and an SHA-256-backed disposable restore drill are documented.                                                                                      | Run isolated production restore drills for data, attachments, login/RLS, reports, keys, and cleanup; measure and approve RPO/RTO before launch; retain controller and incident-commander cutover evidence.        |
| Privacy, retention, and portability            | The data inventory distinguishes financial records, identity/audit data, attachments, payment evidence, and operations data. Audited export, closure/retention, and consent boundaries are documented.                                                                 | Counsel and the privacy officer must approve retention, legal holds, deletion/anonymization, DPA, and response procedures. Use a restricted case record for access, correction, and deletion requests.            |
| Incident response                              | The incident procedure requires severity/triage, containment, evidence preservation, notification decision records, recovery, post-incident review, and tabletop exercises.                                                                                            | Assign an incident commander and privacy/counsel escalation path; preserve logs, audit events, snapshots, and provider evidence before changing affected systems.                                                 |
| Vendor and provider risk                       | Vendor/subprocessor records cover OIDC, payment, email, storage, malware scanning, logging, backup, and hosting. Provider integrations require scoped credentials and acceptance evidence.                                                                             | Record data categories, region, contract owner, security review date, and offboarding plan; complete the applicable row in the [provider gate matrix](PROVIDER_GATE_MATRIX_2026-08-09.md).                        |
| Secure delivery and release                    | Threat-model refresh triggers, pinned CI actions, frozen dependencies, dependency scanning, secrets/static-analysis gates, and backup-restore testing are defined.                                                                                                     | Resolve critical/high threat findings before release and obtain an independent penetration test before broad public release.                                                                                      |

## Minimum production evidence packet

For each control family, retain the responsible owner, approval date, configuration or test
artifact, exceptions, remediation date, and link to the release decision. Development
adapters, local Docker services, or passing local tests do not by themselves satisfy managed
hosting, monitoring, backup, privacy, or independent-review gates.
