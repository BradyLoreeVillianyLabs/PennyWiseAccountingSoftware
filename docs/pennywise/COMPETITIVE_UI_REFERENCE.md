# PennyWise Accounting — Competitive UI Reference

> **Research purpose only.** These sources document useful accounting-workflow patterns. They must not be copied into PennyWise: do not reuse competitors’ logos, screenshots, text, colors, iconography, CSS, layout geometry, or branded interactions. Link to original sources for internal research rather than downloading or rehosting their images.

## Design conclusion

The useful competitive lesson is not “make more cards.” It is to give an accounting user a persistent shell, an efficient transaction workspace, visible task status, contextual detail, and batch-capable actions. PennyWise should translate those behaviors into its own three-beam/pillar identity and a warmer, desktop-grade workbench.

## PennyWise translation rules

1. Copy **workflow principles**, never visual identity.
2. Prefer table-and-inspector workspaces for high-frequency accounting operations.
3. Use summary cards only for summaries, alerts, and short KPIs—not as a substitute for records.
4. Preserve context while users work: account, date range, selected object, task queue, and next action should not require page hopping.
5. Use an original PennyWise layout and brand system: deep navy, warm ivory, muted teal, restrained copper, quiet dividers, and the three-beam/pillar motif.
6. Make accessibility and keyboard efficiency first-class parts of density; compact must never mean cryptic or unusable.
7. Preserve focused work during creation: a missing customer, item, vendor, account, or project
   should be addable beside the picker, with a searchable typed-create path and a clear return to
   the originating draft. Structured tax-code setup may remain a full-form route when jurisdiction
   and component choices are required.

### Layout-stability policy

Report amounts open an in-place inspector or contained detail panel. A source-document review
must return to the same report state, including period, comparison, currency, collapsed groups,
saved-view selection, and table scroll. The table may use sticky headers and a sticky first
column on wide screens, but the mobile fallback remains a horizontally scrollable semantic
table rather than a hidden or truncated number. Print/PDF is a static greyscale output and
does not inherit interactive dashboard controls.
