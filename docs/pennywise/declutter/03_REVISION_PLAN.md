# Revision Plan (phased, gated)

Each phase needs owner authorization in `docs/status/CURRENT_PHASE.md` before any work begins
(AGENTS.md). Each phase finishes with a green `corepack.cmd pnpm check`, e2e, accessibility,
performance and `corepack pnpm test:research` run, plus a refreshed
`COMPETITIVE_RESEARCH_MATRIX.md` entry for every module that was touched.

## Measurable targets (tracked in `docs/pennywise/declutter/metrics.json` by the QA stream)

| Metric                               | Baseline              | Target                              |
| ------------------------------------ | --------------------- | ----------------------------------- |
| Visible nav items (default profile)  | 35 (15 top + 20 rail) | ≤ 10                                |
| Visible buttons on a landing page    | 40–120                | ≤ 12                                |
| Clicks: create and send an invoice   | measure in U0         | ≤ 6                                 |
| Pages with a chart                   | 0                     | Home, every landing, 6 core reports |
| Home fits without scroll at 1366×768 | no                    | yes                                 |

## Risk controls

- **Hide, never delete.** Every removed surface remains reachable by search and deep link until a later,
  separately authorized cleanup.
- **No ledger-logic changes** in U0–U8. Any diff under `packages/accounting-core`, `packages/db` or `apps/api` posting code
  is out of scope and blocks the merge, unless the change is a new read-only summary endpoint with tests.
- Settings and `clearledger_*` storage keys are migrated forward, never renamed.
- Every phase ships behind the UI v2 layout flag (default **off** until the Wave 4 sign-off, then default **on**
  for new installs and opt-in for upgrades during one beta cycle), with a visible "Switch back to classic layout"
  link in Settings. The flag is a device-level `localStorage` key, `pennywise_ui_v2_v1`, read through
  `apps/web/src/ui-flags.js`. It follows the existing `pennywise_owner_workspace_mode_v1` pattern and so needs no
  change to the frozen `WorkflowPreferences` Prisma model. Syncing it per organization would need a separately
  authorized schema change.
